三系统关系

x2cj（翻译）           x2cj-test（验证）              x2cj-eval（静态评估）
──────────             ──────────────              ────────────
Java→仓颉翻译           接收仓颉项目                   LLM 对比 .java↔.cj
  │                      │                              │
  │                      ├─ 编译检查                     ├─ API映射
  │                      ├─ 语义评估 ← 接 x2cj-eval ── ├─ 逻辑一致性
  │                      ├─ 生成Java测试                 ├─ 实现完整性
  │                      ├─ 翻译测试                     ├─ 语义正确性
  │                      └─ 跑测试+修复+报告              └─ 幻觉控制
x2cj-test 是 x2cj 的下游验证系统。x2cj-eval 是入口门禁——编译 + LLM 静态打分，坏翻译在 Stage 2 拦截，不浪费后续 5 个 stage 的测试生成成本。

Agent 流水线

C /goal "x2cj-test 验证 <target> 翻译质量"

Stage 1  Explorer ──→ Gate 1
Stage 2  Compile + x2cj-eval ──→ Gate 2  ← B 入口门禁
           │ PASS (≥75)            FIX (<75)
           ▼                        ▼
Stage 3-7                       退回 x2cj
  Mock→UTGen→Merge→
  TransPrep→Translate
Stage 8  编译修复+运行时修复 ──→ Gate 8
Stage 9  报告生成 ──→ Gate 9 → 🎉
Worker agent（utgen-agent/test-mock-agent/translate-agent/test-fix-agent/review-agent）全部复用现有 agents/ 目录中的定义，不新建。

外部知识

知识源全部来自同一个仓库（Cangjie-SIG/x2cj-skills），agent 按以下顺序加载：

1. skills/x2cj/rules/          ← 已验证 Java→Cangjie 规则（便宜，本地文件）
2. skills/cangjie-dev/         ← 仓颉语言/标准库参考
3. skills/x2cj-eval/skill.md   ← 语义评估标准（14子维度）

加载原则：便宜先查 → 贵后问。已有文档能回答的不用 LLM 推理。
