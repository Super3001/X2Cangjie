# Guard: Stage 3.5 — x2cj-eval 语义验证

## 触发条件

Stage 3 (Compile) 通过后自动触发。不要求目标有测试套件。

## 评估维度

| 维度 | 满分 | 方式 |
|------|:--:|------|
| 编译验证 | 20 | `cjpm build` exit 0 |
| LLM 语义评估（5 子维度） | 30 | LLM 对比 .kt ↔ .cj |
| LLM 性能评估（6 子维度） | 15 | LLM 评估 |
| LLM 代码质量（3 子维度） | 15 | LLM 评估 |
| **合计（跳过测试）** | **80** | |

单元测试 (`cjpm test`) 可选，有则 +20 分（满分 100）。

## PASS 条件

- [ ] 总分 ≥ 60（满分 80，≥75%）
- [ ] 无 `critical` 级别的语义问题
- [ ] 幻觉代码控制子维度 ≥ 6

## FIX 条件

- [ ] 总分 40-59 → 返回 Stage 4 诊断，由 diagnostician 分析 LLM 评估报告中的具体问题
- [ ] 幻觉代码控制 < 6 → 返回 fixer，重点修 stdlib_map 和 render
- [ ] API 映射正确性 < 5 → 返回 fixer，重点修 stdlib_map

## CRITICAL 条件（暂停 loop，人工介入）

- [ ] 总分 < 40 → 大面积语义错误，当前翻译器可能不适合该目标
- [ ] 逻辑一致性 < 3 → 控制流翻译存在系统性缺陷
- [ ] 语义正确性 < 3 → 类型系统映射可能存在根本性错误

## SKIP 条件

- [ ] 无 `.kt→.cj` 文件对可评估（翻译失败率为 100%）→ SKIP，标记 WARNING

## 执行步骤

### Step 1: 编译验证
```bash
cd output/<target>_cj && cjpm build 2>&1
```
exit 0 → 20 分；exit ≠ 0 → 0 分 + CRITICAL

### Step 2: 收集文件对
```bash
# 从 SCAFFOLD/PLAN 或直接扫描收集 .kt↔.cj 文件对
find <target> -name "*.kt" | while read kt; do
    cj="output/<target>_cj/$(basename ${kt%.kt}.cj)"
    [ -f "$cj" ] && echo "$kt → $cj"
done
```

### Step 3: LLM 评估
对每个文件对调用 LLM 三次（语义/性能/质量），评分标准见 `~/x2cj-skills/skills/x2cj-eval/skill.md` Step 5-7。
输出 JSON 到 `output/<target>_cj/reports/x2cj-eval/`。

### Step 4: 汇总
```bash
python3 -c "
import json, glob
scores = []
for f in glob.glob('output/<target>_cj/reports/x2cj-eval/llm_semantic_*.json'):
    scores.append(json.load(open(f)))
total = sum(s['total_score'] for s in scores) / len(scores)
print(f'TOTAL: {total}/80')
"
```
