# Guard: Stage 3.5 — Semantic Verify 验收

## 触发条件

Stage 3 (Compile) 通过后，且目标代码库**有可运行的测试套件**时触发。
如果目标无测试套件，跳过此 stage（标记为 SKIP），不阻塞收敛。

## 测试套件检测

```bash
# Gradle 项目
test -f <target>/build.gradle* && grep -q "test" <target>/build.gradle* && echo "HAS_TESTS"

# Maven 项目
test -f <target>/pom.xml && grep -q "junit\|testng\|kotlintest" <target>/pom.xml && echo "HAS_TESTS"
```

## PASS 条件（差分测试）

### Step 1: 跑原始 Kotlin 测试
```bash
cd <target>
./gradlew test 2>&1 | tee /tmp/kotlin_test_output_r<N>.log
echo "KOTLIN_TESTS_PASS: $(grep -c 'PASSED\|SUCCESS' /tmp/kotlin_test_output_r<N>.log)"
```

### Step 2: 翻译测试文件
```bash
kotlin2cj <target>/src/test/ -o output/<target>_cj_test/
```

### Step 3: 跑仓颉翻译测试
```bash
cd output/<target>_cj_test
cjpm test 2>&1 | tee /tmp/cangjie_test_output_r<N>.log
echo "CANGJIE_TESTS_PASS: $(grep -c 'PASSED\|OK' /tmp/cangjie_test_output_r<N>.log)"
```

### Step 4: 对比
- [ ] 仓颉测试通过数 == Kotlin 测试通过数
- [ ] 无测试超时（> 60s per test）
- [ ] 无 panic / crash

## FIX 条件（语义漂移）

- [ ] Kotlin 测试通过但仓颉测试失败 → **SEMANTIC_DRIFT**，最高优先级
- [ ] 仓颉测试超时 → 可能是无限循环，标记 FIX
- [ ] 仓颉测试 panic → 标记 FIX

## SKIP 条件

- [ ] 目标无测试套件 → SKIP，记录 WARNING，不阻塞收敛
- [ ] Kotlin 测试本就不通过（源项目有 bug） → SKIP，记录原因

### 静态语义差异检测
编译时就能发现的语义问题，不计入 FAIL 但标记 WARNING：
- `Int`(32-bit) → `Int64`(64-bit)：溢出边界不同
- `Char`(UTF-16) → `Rune`(Unicode scalar)：surrogate pair 处理
- `==` structural vs referential：Kotlin 有两套，仓颉只有一套
