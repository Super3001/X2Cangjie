# kotlin2cj 优化目标体系

> 本系统优化的不是翻译速度或内存占用，而是 **翻译器的语法覆盖广度 × 语义正确深度**。

---

## 一、第一性目标（不可妥协）

### G1. 零编译错误

**定义**：目标代码库翻译为仓颉后 `cjpm build` exit 0。

**测量**：`cjpm build 2>&1 | grep -c "error"` 必须为 0。

**为什么是第一性**：编译错误 = 翻译器不认识某个 Kotlin 语法结构，或把它翻成了不合法的仓颉。每个编译错误都是一个 **PARSER_GAP / RENDER_GAP / HEURISTIC_GAP / STDLIB_GAP / NODE_GAP**。消除它们就是在填补翻译器的能力窟窿。

### G2. 零回归

**定义**：对已有测试用例的翻译输出不能退化。

**测量**：
- 187 个单文件测试全部 `diff` 通过
- 32 个项目测试全部通过
- 新增修复不能改变已有 `.expected` 文件（除非刻意改进翻译质量）

**为什么是第一性**：G1 可能在修补中破坏已有能力。G1 和 G2 相互制衡——一个推动前进（覆盖新语法），一个防止后退（丢失旧能力）。

## 二、SOC 维度目标

### G3. 雪崩规模幂律分布

**定义**：`relax_soc()` 输出的 `grain_avalanches` 序列应呈现幂律分布——少数节点引发大级联，大多数节点局部稳定。

**测量**：`--soc-analysis` 输出 `SOC_GRAIN_AVALANCHES` 序列，拟合幂律指数 α。

**为什么重要**：当翻译器的规则库越来越庞大时，幂律分布是"系统仍处于临界态"的信号。如果分布偏离幂律（比如大雪崩占比骤升），说明某处修改破坏了局部性——一个改动引发了远超出预期的级联。

### G4. 张力收敛速度

**定义**：每轮 fixer 修改后，下一轮 translator+compiler 的错误减少量。

**测量**：`state/optimization-state.md` 中每轮的 `错误: N → M`。计算 `(N-M)/N` 作为收敛效率。

**为什么重要**：如果连续 3 轮错误数不变（FIX_STUCK），说明当前策略遇到了深层语义错配——需要升级到 L3 级架构改动，或标记为红区（"需要人"）。

## 三、翻译质量维度目标（当前未测量，未来应加入）

### G5. 翻译产物覆盖率

**定义**：目标代码库中每个 `.kt` 文件都生成了对应的 `.cj` 文件，无翻译失败的空白文件。

**测量**：`find output/<target>_cj -name "*.cj" | wc -l` 与源文件数对比。

### G6. 惯用法评分（未来）

**定义**：翻译产物的"Cangjie 味儿"。不是直译腔的 Kotlin，而是读起来像人写的仓颉。

**测量**（SOC 理论中的 T_idiom 代理）：
- 仓颉代码语言模型的困惑度
- 人为可检查：`forEach` → `for` 循环、`?.let` → `if let Some`、`!!` → `getOrThrow()` 的比例

### G7. 测试密度

**定义**：每修复一个 gap 类型，至少新增一个针对性测试用例。

**测量**：`tests/cases/` 目录中测试用例数量增长曲线。当前基线：219（187 单文件 + 32 项目）。

## 四、多目标推演维度

### G8. 跨目标泛化

**定义**：在目标 A 上修的 bug，是否也让目标 B 的编译错误减少了。

**测量**：修完 ksoup 后，跑 okhttp 的翻译+编译，看错误数是否比"从未修过 ksoup 的基线翻译器"少。

**为什么重要**：这是翻译器"真正变聪明了"还是"只对 ksoup 过拟合了"的区分标准。SOC 理论第十节的可检验预言 3（消融实验）就是测这个。

### G9. 目标覆盖率递增

**定义**：候选库中已收敛（0 errors）的目标数。

**测量**：轮换表里 `状态 = ✅ 收敛` 的条目数。

```
ksoup     → ✅ 收敛（R3）         ← G1 达成
okhttp    → 剩余 12 errors（R1）  ← 正在优化
ktor      → 🔒 候选
exposed   → 🔒 候选
mockk     → 🔒 候选
```

## 五、目标间约束关系

```
        G1（零编译错误）
        ↗         ↖
   G2（零回归）   G3（幂律分布）
        ↖         ↗
        G4（收敛速度）
             │
    ┌────────┼────────┐
    │        │        │
   G5       G6       G7
（覆盖率）（惯用法）（测试密度）
             │
        ┌────┴────┐
        │         │
       G8        G9
   （跨目标）  （覆盖率递增）
```

G1+G2 是硬约束（gate 不通过不进下一阶段），G3+G4 是 SOC 理论自带的观测指标，G5-G7 是品质维度，G8+G9 是多目标推演。
